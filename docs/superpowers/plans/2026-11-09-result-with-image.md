# YAIC Result With Image Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for task-by-task execution after the user requests implementation. Current scope is planning only.

**Goal:** Публиковать результат YAIC и исходный снимок одним MQTT JSON.

**Architecture:** MqttClient дополняет копию ProcessingResult.payload полем image_b64 из ProcessingResult.image_bytes. Processor и автономные JSONL-команды сохраняют прежний контракт; параметры лимита задаются через Config.

**Tech Stack:** Python, base64/json стандартной библиотеки, существующий paho-mqtt, pytest; без новых runtime-зависимостей.

**Spec:** [Согласованное направление и предлагаемые детали](../specs/2026-11-09-result-with-image-design.md).

## Global Constraints

- Только план на этом этапе; без изменений приложения, коммитов, делегирования реализации и деплоя.
- При реализации сохранить существующие незакоммиченные изменения; не выполнять reset/checkout файлов.
- Не возвращать HA discovery или отдельные фиксированные топики изображений.
- Не включать адреса серверов, SSH, секреты и частные инструкции обновления в репозиторий.
- Использовать `.venv/bin/python -m pytest`; после каждого изменения кода запускать тесты.
- Не добавлять Telegram, хранение фото, фильтрацию людей, дедупликацию или новую обработку Tuya.
- 16 MiB и сохранение CLI без фото — предложения автора плана, а не отдельные требования пользователя.

## Review Focus

- URL может вернуть другой кадр при повторном запросе: исходные байты используются один раз (Task 1).
- Смешение двух камер и потеря event_id: байты и поля должны соответствовать одному результату (Task 1).
- Изменение общего payload не должно раздувать CLI JSONL (Task 1).
- Рост JSON и точная граница лимита; недоступность брокера в момент publish (Task 2).
- Повторная доставка QoS 1 и старые очереди не должны описываться как exactly-once/freshness guarantee (Task 2, документация и smoke-test).

## Task 1: Самодостаточный MQTT результат

**Files:** `yaic/mqtt_client.py`, `tests/test_mqtt_client.py`; при необходимости расширить `tests/test_processor.py` и `tests/test_main.py`.

**Interfaces:** `ProcessingResult.payload`, `.image_bytes`; MQTT_TOPIC_OUT без изменения маршрутизации. Добавляем только `image_b64: str` в MQTT JSON.

- [ ] Добавить тест `test_result_contains_original_image`: после публикации `base64.b64decode(output['image_b64'], validate=True) == result.image_bytes`; остальные поля совпадают с исходным payload, исходный payload не изменён.
- [ ] Добавить проверку двух камер с разными байтами, source/device/event_id; исходный отсутствующий event_id остаётся отсутствующим. Проверить результат person и результат без людей.
- [ ] Для binary, base64 и URL прогнать связку реального Processor с fake VLM через MqttClient; HTTP подменять на границе транспорта. Декодированное фото равно байтам, переданным VLM; для URL ровно одна загрузка.
- [ ] Проверить одну публикацию результата в настроенный топик с qos=1, retain=False и отсутствие изображения/base64 в логах. Существующие CLI-тесты дополнить проверкой отсутствия image_b64 в JSONL.
- [ ] Запустить `.venv/bin/python -m pytest tests/test_mqtt_client.py tests/test_processor.py tests/test_main.py -q`; подтвердить новые ожидаемые падения.
- [ ] В `_on_message` собрать копию словаря результата с `image_b64=base64.b64encode(result.image_bytes).decode('ascii')`, затем сериализовать. В publish явно указать retain=False. Не менять Processor и не читать исходный MQTT JSON повторно.
- [ ] Повторить целевые тесты, затем полный `.venv/bin/python -m pytest`.

## Task 2: Размер, ошибки публикации и документация

**Files:** `yaic/config.py`, `yaic/mqtt_client.py`, `tests/test_config.py`, `tests/test_mqtt_client.py`, `README.md`, `docker-compose.yaml`.

**Interfaces:** `Config.mqtt_max_output_bytes: int = 16777216`; env `MQTT_MAX_OUTPUT_BYTES`; измерение `len(serialized.encode('utf-8'))`. Ошибка использует существующий operation status error.

- [ ] Написать тесты Config: значение по умолчанию, положительное переопределение; 0, отрицательное и нецелое отвергаются с понятной ошибкой.
- [ ] Написать тесты размера: JSON ровно на границе проходит; на один байт больше не публикуется; счёт ведётся по окончательной UTF-8 сериализации, включая base64 и метаданные. Лимит в тестах задаётся малым; большие фотографии не нужны.
- [ ] FakeMqttClient.publish должен возвращать объект с rc как реальный клиент. Проверить ненулевой rc и исключение именно при публикации результата: operation=error, отсутствие idle, отсутствие fallback-результата без фото. Успех сохраняет idle.
- [ ] Запустить целевые тесты и подтвердить ожидаемые падения.
- [ ] Реализовать чтение/валидацию лимита, проверку перед publish и обработку немедленных ошибок. Не добавлять wait_for_publish в MQTT callback, outbox или новую систему повторной доставки.
- [ ] Обновить README: пример JSON с image_b64, значение лимита, QoS/retain и семантика idle; сохранить описание старых полей. Добавить переменную в compose без изменения частных окружений.
- [ ] Запустить `.venv/bin/python -m pytest` и `git diff --check`. Если локальных optional face-зависимостей нет, явно отразить блокировку и выполнить полный набор в тестовом контейнере со всеми зависимостями; не подменять отсутствующие модули фиктивными.
- [ ] Выполнить изолированный MQTT smoke-test: временный брокер и синтетический VLM, послать снимок, получить один полный JSON, декодировать и сравнить байты. Новый подписчик с чистой сессией не получает retained результат. Не использовать действующие камеры, рабочие топики или реальный VLM.

## Критерий готовности и последующий этап

Любой успешный MQTT результат в пределах лимита содержит соответствующий снимок;
все прежние поля сохранены, CLI не меняется, ошибки не выглядят как успешная
публикация. Полный набор тестов и изолированный обмен MQTT проходят.

До отдельного деплоя проверить лимиты брокера и потребителей, совместимость
строгих схем и размер типичных сообщений. Адреса и команды конкретного сервера
остаются в частных локальных заметках. После готовности YAIC планировать
MQTT → Telegram как самостоятельный сервис.
