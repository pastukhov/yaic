# YAIC без обязательного Home Assistant

## Запрос и текущее устройство

Пользователь попросил изучить YAIC, составить план освобождения от Home Assistant
и делегировать реализацию Sol. Дополнительный цикл согласования не требуется:
выбор исполнителя и выполнение уже запрошены. Ниже инженерные решения, а не
утверждение, что пользователь согласовал каждую CLI-опцию.

Изучены yaic/main.py, config.py, processor.py, mqtt_client.py, api.py,
role_classifier.py, face_recognition.py, тесты и HA blueprint. Processor уже
принимает байты, base64 и URL. VLM/FaceRecognizer не требуют HA. Обязательны
MQTT-параметры и MQTT lifecycle в main; discovery вызывается без переключателя.
HTTP API только управляет индексом лиц и запускается вместе с Chroma.
HA blueprint выполняет цепочку ipc_human → camera.snapshot → MQTT → уведомление.

## Подходы

1. Отдельный Tuya→MQTT мост: минимум изменений, но сохраняет обязательный брокер.
2. Самостоятельный runtime YAIC с общим Processor и отдельными входами: выбран
   как наиболее прямой путь к работе без HA и без обязательного MQTT.
3. Новая HTTP-служба и полный рефакторинг: лишняя инфраструктура для текущего этапа.

## Первая реализация

- Сохранить запуск `yaic` без аргументов как существующий MQTT-режим.
- Добавить `yaic classify --image FILE --source-id ID`: один снимок → один JSON.
- Добавить `yaic listen-tuya --device-config PATH --source-id ID`: события JSONL.
  Без флага `--classify` не вызывать VLM и не загружать снимки.
- С `--classify` использовать тот же Processor. Для ipc_human брать снимок из
  явно заданного YAIC_SNAPSHOT_URL (HTTP(S), без HA-зависимости). DP154 может
  предоставить собственный подписанный HTTPS URL снимка звонка.
- Если доступного снимка нет, выводить snapshot_unavailable, не классифицировать
  старый снимок и не подставлять фиктивное изображение.
- Результаты/события в stdout JSONL; диагностика standalone-команд в stderr.
- Опциональный HA discovery: HA_DISCOVERY_ENABLED=false отключает discovery,
  сохраняя обычные MQTT topics. По умолчанию совместимость сохраняется.
- Общая фабрика Processor сохраняет VLM, опциональное узнавание лиц и роли.
  Не менять семантику классификации/порогов в этой задаче.

## Проверенная основа Tuya и пробел

Ссылки на локальное исследование:
/home/artem/repos/домофон/docs/06-lan-protocol-validation.md,
docs/evidence/listen-lan-call.py, docs/evidence/lan-human-event-summary.json.
Устройство LAN3.3, TinyTuya1.20.0, dev_type=device22; socketRetryLimit=1,
socketTimeout=2, persistent=true. Однократный status с dps_to_request
109,110,136,239,240,243,244 (null) получает отдельные ответы и push.
DP239/240 Ring/Normal; DP185 Base64 JSON с cmd=ipc_human, v=3.0,
type=image, with=resources, files=[[resource_path, 16-character-value]].
Значение v=3.0 не является версией LAN. DP154 Base64 HTTPS URL с подписью.

Получение/расшифровка изображения из DP185 НЕ установлены. Не конструировать
URL из bucket/path и не называть 16-символьное поле проверенным ключом AES.
DP154 URL также ещё не проверен на реальное декодируемое изображение.
У сохранённого DP154 X-Amz-Expires=60 секунд; ссылка уже просрочена. Очередь
не должна превращать событие в поздний снимок другого человека: отклонять
задания старше 5 секунд до загрузки и сообщать snapshot_unavailable. Это
осознанный компромисс первой версии: при медленном VLM часть кадров пропускается.
Транспорт события локальный; снимок DP154 облачный; WAN-независимость не доказана.
Отдельный последующий эксперимент нужен для полноценного человека-в-кадре
без настроенного внешнего snapshot endpoint. Первую реализацию не выдавать
за завершённую сквозную интеграцию физического домофона.

## Надёжность и ограничения

- Известные null-запросы чтения и heartbeat; никаких DP set, замков, reset/OTA.
- Чтение Tuya не блокируется VLM: ограниченная очередь, один worker, отказ от
  новых задач при переполнении с диагностикой. Короткий ring/status не требует VLM.
- Дедупликация одинакового уведомления ограничена по времени и объёму;
  повторное реальное событие после окна снова обрабатывается.
- Переподключение с ограниченной задержкой, SIGINT/SIGTERM закрывают socket;
  длительность уже начатого inference ограничена существующими timeout/retries
  и должна быть честно описана. Не добавлять неподтверждённые протокольные команды.
- Snapshot загрузчик: HTTP(S), timeout, ограничение 10 MiB, проверка изображения
  перед VLM, без HA токена и без вывода URL/query/resource/key в ошибки.
  Это распространяется и на информационные журналы httpx/httpcore.
- local_key только из указанного внешнего JSON (id, ip, local_key, version).
  Не копировать реальные ключи, изображения, URL или private logs в репозиторий.
- Никаких live VLM вызовов, перезапусков сервисов, push/deploy и изменения .env
  в рамках автоматических проверок. Fixture и fake transport достаточны для кода.
- Существующий untracked docs/yaic_image_url_support.md не менять.
- Python >=3.11. Минимальные изменения; существующий MQTT и face режим сохранить.

## Проверка результата

Запуск classify и listen-tuya не должен требовать MQTT_* или HA_TOKEN.
Мокированный сквозной тест событие→снимок→Processor→JSONL доказывает связку кода;
реальная камера и доставка уведомлений на телефон в этот критерий не входят.
Для будущей полноценной проверки нужен свежий снимок реального Tuya-события.
